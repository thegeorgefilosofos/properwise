# Κόκκινη δοκιμή πρώτα

Ο κανόνας του αποθετηρίου: **κάθε διόρθωση σφάλματος φέρνει δοκιμή που
αποδεδειγμένα αποτυγχάνει στον παλιό κώδικα.** Αν δεν την είδες κόκκινη, δεν
ξέρεις αν ελέγχει αυτό που νομίζεις.

```
ΚΑΝΕΝΑΣ ΚΩΔΙΚΑΣ ΠΑΡΑΓΩΓΗΣ ΧΩΡΙΣ ΔΟΚΙΜΗ ΠΟΥ ΑΠΕΤΥΧΕ ΠΡΩΤΑ
```

## Γιατί, από αυτό το αποθετήριο

Στον φύλακα `scripts/guard-test-tail.mjs`: έλεγχοι προστέθηκαν με `>>` στο τέλος
αρχείου δοκιμών, **μετά** τη γραμμή που βγάζει τον κωδικό εξόδου. Εκτελούνταν,
δεν μετρούσαν. Εγινε τρεις φορές μέσα στην ίδια μέρα. Την πρώτη φορά το σφάλμα
φάνηκε **μόνο επειδή η σουίτα έτρεξε και με τον παλιό κώδικα: πέρασε κι εκεί.**

Στον `scripts/guard-billing-claims.mjs`: το θέμα «δοκιμ» δεν ταίριαζε με το
«δοκίμασε», γιατί το «ί» δεν είναι «ι». Η δοκιμή που ξαναέβαλε τη φράση
πέρασε πράσινη. Μια δοκιμή που δεν κοκκίνισε ποτέ δεν είναι ουδέτερη· το
πράσινό της διαβάζεται ως «ελέγχθηκε».

## Ο κύκλος

### 1. ΚΟΚΚΙΝΟ: μία δοκιμή, μία συμπεριφορά

Δίπλα στον κώδικα, `*.test.ts`. Ο `scripts/test.mjs` τη βρίσκει μόνος του·
δεν τη δηλώνεις πουθενά.

- Ονομα που λέει τη συμπεριφορά. «και» στο όνομα; Χώρισέ τη.
- **Πριν τη γράψεις, πες ποια αλλαγή στον κώδικα θα την έκανε κόκκινη.** Αν δεν
  μπορείς, ελέγχει το πλαίσιο, όχι τον κώδικά σου.
- Αναμενόμενες τιμές γραμμένες ανεξάρτητα: κυριολεκτικές, ελεγμένες με το χέρι.
  Οχι υπολογισμένες με την ίδια συνάρτηση που ελέγχεις.
- Πραγματικός κώδικας. Mock μόνο για δίκτυο, Supabase ή χρόνο. Τότε ο
  ισχυρισμός πάει στο αποτέλεσμα, όχι στο ότι κλήθηκε το mock.
- Φορολογικές τιμές: η δοκιμή χρησιμοποιεί τη σταθερά του `lib/tax/**`, ή την
  τιμή της πηγής (ΦΕΚ) με την πηγή σε σχόλιο. Ποτέ αριθμός χωρίς προέλευση.

### 2. Δες την κόκκινη. ΥΠΟΧΡΕΩΤΙΚΟ

```
npx tsx lib/x/onoma.test.ts
```

Η εντολή τρέχει **μόνη της**. Οχι `| tail`, όχι `; echo $?`: το εργαλείο σού
δίνει ήδη τον κωδικό εξόδου, ο σωλήνας τον αλλάζει.

- Αποτυγχάνει με το μήνυμα που περίμενες; Συνέχισε.
- Σκάει με σφάλμα (εισαγωγή, τυπογραφικό); Διόρθωσε και ξανατρέξε ώσπου να
  αποτύχει **για τον σωστό λόγο**.
- Περνά; Ελέγχεις κάτι που ήδη ισχύει. Διόρθωσε τη δοκιμή.

**Για διόρθωση σφάλματος που ο κώδικας έχει ήδη γραφτεί**, απόδειξέ το στον
παλιό κώδικα:

```
git stash push -- lib/x/onoma.ts
npx tsx lib/x/onoma.test.ts
git stash pop
```

ή σε δεύτερο worktree στο `origin/main`. Γράψε στην περιγραφή του PR τι είδες:
«κόκκινη στο main με "<μήνυμα>", πράσινη εδώ».

### 3. ΠΡΑΣΙΝΟ: ο ελάχιστος κώδικας

Οσο χρειάζεται για να περάσει η δοκιμή. Χωρίς επιλογές που δεν ζήτησε κανείς,
χωρίς αναδιάρθρωση γειτονικού κώδικα.

### 4. Δες την πράσινη μαζί με όλη τη σουίτα

```
npm test
```

Η πράσινη δοκιμή σου δεν είναι πράσινη σουίτα. Ο,τι άλλο κοκκινίσει, ακόμη κι
αν δεν το προκάλεσες εσύ, γράφεται με το όνομά του στην αναφορά σου. Κόκκινη
γραμμή που την είδες να περνά και δεν την ανέφερες είναι αναφορά που λέει ψέματα.

### 5. Καθάρισμα

Μόνο με πράσινο. Ονόματα, επαναλήψεις, βοηθητικά. Καμία νέα συμπεριφορά.

## Πού δεν εφαρμόζεται ως έχει

Δεν είναι κάθε αλλαγή κώδικας με συμπεριφορά. Εκεί η απόδειξη αλλάζει μορφή,
δεν εξαφανίζεται:

| Αλλαγή | Η «κόκκινη» απόδειξη |
|---|---|
| Νέος φύλακας `scripts/guard-*.mjs` | μετάλλαξη στο `scripts/lib/mutations.mjs` (skill `fylakas`) |
| Μετανάστευση στο `supabase/migrations/**` | το ερώτημα που αποτυγχάνει πριν, π.χ. RLS που αφήνει ξένο χρήστη να διαβάσει |
| Κείμενο, λεκτικά, τεκμηρίωση | `npm run guards` |
| Καστάνια | η μέτρηση πριν και μετά (skill `kastania`) |
| Οπτική αλλαγή | στιγμιότυπο πριν και μετά, σε φωτεινό και σκοτεινό θέμα |

## Δικαιολογίες που ακούγονται συχνά

| Δικαιολογία | Τι ισχύει |
|---|---|
| «Πολύ απλό για δοκιμή» | Ο απλός κώδικας σπάει. Η δοκιμή θέλει μισό λεπτό. |
| «Θα γράψω τη δοκιμή μετά» | Δοκιμή γραμμένη μετά περνά αμέσως. Δεν απέδειξε ότι πιάνει το σφάλμα. |
| «Το έλεγξα με το χέρι» | Δεν ξανατρέχει, δεν καταγράφεται. Ο επόμενος δεν ξέρει τι ελέγχθηκε. |
| «Ο κώδικας ήδη υπάρχει, κρατάω τη δοκιμή για μετά» | Τότε απόδειξέ τη στον παλιό κώδικα (βήμα 2). Αλλιώς δεν μπαίνει. |
| «Η δοκιμή περνά, άρα όλα καλά» | Αν πέρασε από την αρχή, δεν ελέγχει τίποτα καινούριο. |

## Ελεγχος πριν από «έγινε»

- [ ] Κάθε νέα συνάρτηση έχει δοκιμή.
- [ ] Είδα κάθε δοκιμή κόκκινη, για τον σωστό λόγο.
- [ ] Για διόρθωση: κόκκινη στον παλιό κώδικα, γραμμένο στο PR.
- [ ] `npm test` πράσινο, χωρίς προειδοποιήσεις που δεν υπήρχαν.
- [ ] Τα σενάρια αποτυχίας (κενό, μηδέν, έτος χωρίς δεδομένα) έχουν δοκιμή.

Για τον έλεγχο πριν από κάθε ισχυρισμό ολοκλήρωσης: `verification-before-completion`.
Για εντοπισμό αιτίας πριν από τη δοκιμή: `systematic-debugging`.
