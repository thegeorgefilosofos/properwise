# Νέος φύλακας

Ενας φύλακας δεν είναι δοκιμή. Η δοκιμή λέει ότι μια συνάρτηση κάνει αυτό που
υπόσχεται· ο φύλακας λέει ότι μια ΚΑΤΗΓΟΡΙΑ λάθους δεν υπάρχει πουθενά στο
αποθετήριο. Γι' αυτό σαρώνει αρχεία, όχι συμπεριφορά.

## Πότε γράφεται φύλακας και πότε όχι

**Ναι**, όταν η απάντηση «σωστό ή λάθος» μπορεί να γραφτεί ως συνάρτηση πάνω σε
κείμενο αρχείων: μια λέξη που δεν γράφεται, ένας αριθμός γραμμένος με το χέρι
εκεί που υπάρχει όνομα, μια υπόσχεση σε οθόνη που ο κώδικας δεν τηρεί, δύο πηγές
για το ίδιο πράγμα.

**Οχι**, όταν χρειάζεται κρίση. «Η απόσταση φαίνεται σφιχτή» δεν γίνεται φύλακας.
Γίνεται σαρωτής διάταξης, ή δεν γίνεται τίποτα.

## Τα βήματα

### 1. Γράψε το αρχείο

`scripts/guard-<όνομα>.mjs`. Δεν χρειάζεται καμία δήλωση πουθενά: ο
`scripts/run-guards.mjs` ανακαλύπτει από το σύστημα αρχείων κάθε `guard-*.mjs`
του `scripts/`. Η κατηγορία «γραμμένος και μη συνδεδεμένος» είναι αδύνατη — και
έγινε τρεις φορές πριν γίνει αδύνατη.

Το σχήμα, όπως το γράφουν οι υπόλοιποι:

```js
#!/usr/bin/env node
// ═══════════════════════════════════════════════════════════════════════════
// Ο ΤΙΤΛΟΣ ΕΙΝΑΙ Ο ΚΑΝΟΝΑΣ, ΣΕ ΜΙΑ ΓΡΑΜΜΗ, ΜΕ ΚΕΦΑΛΑΙΑ
// ─────────────────────────────────────────────────────────────────────────
// ΤΟ ΠΕΡΙΣΤΑΤΙΚΟ, ΜΕΤΡΗΜΕΝΟ. Τι έσπασε στ' αλήθεια, με αριθμό: πόσες φορές,
// σε πόσα αρχεία, τι κόστισε. Χωρίς περιστατικό δεν μπαίνει φύλακας — αλλιώς
// ο επόμενος δεν ξέρει αν διορθώνει σφάλμα ή προτίμηση.
//
// ΤΙ ΕΛΕΓΧΕΤΑΙ, ΑΚΡΙΒΩΣ. Ποια αρχεία, ποιο μοτίβο, ποιες εξαιρέσεις και ΓΙΑΤΙ
// η καθεμία.
// ═══════════════════════════════════════════════════════════════════════════
import { readFileSync } from 'node:fs'
import { projectFiles } from './lib/git-files.mjs'

const files = projectFiles("'app/**/*.tsx' 'lib/**/*.ts'")
const provlimata = []
// …
if (provlimata.length) {
  console.error(`\n✗ ${provlimata.length} …:\n`)
  for (const p of provlimata.slice(0, 30)) console.error(`  ${p.arxeio}:${p.grammi}  «${p.ti}»`)
  console.error(`\n  ΤΙ ΝΑ ΚΑΝΕΙΣ: …\n`)
  process.exit(1)
}
console.log(`✓ … σε ${files.length} αρχεία`)
```

Τρεις κανόνες για το μήνυμα αποτυχίας:

- **αρχείο:γραμμή**, πάντα. Χωρίς αυτό ο φύλακας μετατοπίζει τη δουλειά, δεν την κάνει.
- **Τι να κάνεις**, όχι μόνο τι βρήκε.
- **Κόψε στα 30** και πες πόσα έμειναν. Χίλιες γραμμές στο τερματικό δεν διαβάζονται.

### 2. Χρησιμοποίησε το `projectFiles`, όχι το `git ls-files`

Το `scripts/lib/git-files.mjs` επιστρέφει καταχωρημένα **και** νέα αρχεία. Ενας
φύλακας που ρωτά σκέτο `git ls-files` είναι τυφλός ακριβώς στο παράθυρο όπου
γράφεται ο νέος κώδικας — συνέβη και ένας χειριστής webhook πέρασε καθαρός από
66 φύλακες.

Και πρόσεξε το pathspec: το `'components/**/*.tsx'` του git **δεν** πιάνει τη
ρίζα του φακέλου. Δέκα φύλακες το έγραφαν και δεν έλεγχαν κανένα από τα
δεκαεπτά αρχεία του `components/`. Το `projectFiles` το διορθώνει μόνο του, γι'
αυτό περνά κανείς από εκεί.

### 3. Πρόσεξε τι αγνοεί το αποθετήριο

Πριν γράψεις φύλακα για έναν φάκελο, τρέξε:

```
git check-ignore -v <διαδρομή>
```

Το `docs/marketing/posts/*` και το `docs/marketing/reels/*` αγνοούνται
ολόκληρα: είναι παραγόμενα. Φύλακας πάνω σε αγνοημένο φάκελο μένει πράσινος
για πάντα και δεν το λέει κανείς. Εγινε — και το `guard-post-numbers.mjs`
ξαναγράφτηκε γι' αυτόν ακριβώς τον λόγο.

### 4. ΑΠΟΔΕΙΞΕ ΤΟΝ ΜΕ ΜΕΤΑΛΛΑΞΗ — χωρίς αυτό δεν υπάρχει

Πρόσθεσε εγγραφή στο `scripts/lib/mutations.mjs`. Τρεις μορφές:

```js
'onoma': { add: 'components/__mut__.tsx', content: tsx('    <div>το σφάλμα</div>') },
'onoma': { file: 'lib/x.ts', from: 'σωστό', to: 'λάθος' },
'onoma': { every: [ { add: … }, { add: … } ] },
```

Η μετάλλαξη εισάγει **ακριβώς** το σφάλμα για το οποίο γράφτηκε ο φύλακας. Μετά:

```
node scripts/verify-guards.mjs <όνομα>; echo "κωδικός: $?"
```

Ο πάγκος τρέχει τον φύλακα πριν (απαιτεί πράσινο), βάζει τη μετάλλαξη, ξανατρέχει
(απαιτεί κόκκινο) και επαναφέρει το δέντρο πάντα. Φύλακας χωρίς μετάλλαξη είναι
αποτυχία, όχι παράλειψη: ο ίδιος ο πάγκος το επιβάλλει.

**Σε μία εβδομάδα βρέθηκαν τρεις φύλακες που τύπωναν πράσινο πάνω από πραγματικά
σφάλματα.** Ενας φύλακας που δεν κοκκινίζει ποτέ δεν είναι ουδέτερος· είναι
χειρότερος από ανύπαρκτος, γιατί το πράσινό του διαβάζεται ως «ελέγχθηκε».

### 5. Τρέξε ΧΩΡΙΣ σωλήνα

```
npm run guards; echo "κωδικός: $?"
```

**Ποτέ `npm run guards | tail -4`.** Ο κωδικός εξόδου ενός σωλήνα είναι του
τελευταίου προγράμματος — δηλαδή του `tail`, που πάντα επιτυγχάνει. Κόκκινος
φύλακας περνά για πράσινος και το `&&` της επόμενης εντολής εκτελείται.

Αυτό συνέβη σε αυτό το αποθετήριο και δέθηκε commit με κόκκινο φύλακα μέσα του.
Αν χρειάζεσαι λιγότερη έξοδο: `npm run guards > /tmp/g.txt 2>&1; echo "$?"` και
μετά διάβασε το αρχείο.

## Ο τελικός έλεγχος

| | |
|---|---|
| Το αρχείο | `scripts/guard-<όνομα>.mjs`, με περιστατικό στην κεφαλή |
| Η σύνδεση | αυτόματη — καμία ενέργεια |
| Η απόδειξη | εγγραφή στο `scripts/lib/mutations.mjs` |
| Ο κωδικός μετάλλαξης | `verify-guards` δίνει 0, δηλαδή κοκκίνισε και ξαναπρασίνισε |
| Η συνολική εκτέλεση | `npm run guards` χωρίς σωλήνα, κωδικός 0 |
