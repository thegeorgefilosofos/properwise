# Παράλληλοι πράκτορες

Ενας πράκτορας ανά ανεξάρτητο πεδίο, όλοι ταυτόχρονα. Εσύ γράφεις τις αναθέσεις,
περιμένεις, ελέγχεις τα αποτελέσματα μαζί.

## Πότε ναι, πότε όχι

**Ναι**, όταν κάθε πρόβλημα καταλαβαίνεται χωρίς τα άλλα και κανένα δεν γράφει
σε αρχείο που γράφει άλλο.

**Οχι**, όταν:

- τα σφάλματα μπορεί να έχουν κοινή αιτία (διόρθωσε το ένα, φεύγουν όλα)·
- δεν ξέρεις ακόμη τι έσπασε: πρώτα `systematic-debugging`, μετά μοίρασμα·
- δύο δουλειές αγγίζουν το ίδιο αρχείο, την ίδια μετανάστευση ή την ίδια
  βάση καστάνιας. Θα συγκρουστούν στη συγχώνευση. Βάλ' τες στη σειρά.

## Τα όρια

**Το πολύ τρεις με τέσσερις ταυτόχρονα.** Πάνω από αυτό το μηχάνημα δεν σηκώνει
τις σουίτες και τα build, οι εργασίες CI στοιβάζονται και ο συντονισμός σου
χάνει την εικόνα. Αν έχεις έξι δουλειές, τρέχεις τρεις· μόλις τελειώσει μία
ξεκινάς την επόμενη.

**Ενα worktree και ένα κλαδί ανά πράκτορα.** Ποτέ δύο πράκτορες στον ίδιο
φάκελο ή στο ίδιο κλαδί: ο ένας σβήνει τις αλλαγές του άλλου και το CI τρέχει
διπλό. Το worktree φτιάχνεται από το `origin/main`:

```
git fetch origin main
git worktree add -b claude/<θέμα> <scratchpad>/<θέμα>-wt origin/main
```

**Δικές του θύρες.** Αν ο πράκτορας σηκώνει `next dev` ή `next start`, του δίνεις
θύρα που δεν χρησιμοποιεί άλλος (3101, 3102, …).

**Κανένα `pkill` ή `killall`.** Σκοτώνει τους διακομιστές και τις σουίτες των
άλλων πρακτόρων στο ίδιο μηχάνημα. Ο καθένας σταματά μόνο ό,τι ξεκίνησε, με το
PID του.

## Το μήνυμα ανάθεσης: αυτοτελές

Ο πράκτορας δεν βλέπει τη συνομιλία σου. Ό,τι δεν είναι στο μήνυμα δεν υπάρχει.

```
Στόχος: <μία πρόταση, ένα πεδίο>.

Πλαίσιο: <τα μηνύματα σφάλματος αυτούσια, τα ονόματα δοκιμών, οι διαδρομές>.

Φάκελος: <worktree>. Κλαδί: claude/<θέμα>. Θύρα: <αν χρειάζεται>.

Περιορισμοί:
- Μόνο <αρχεία ή φάκελοι>. Τίποτε άλλο.
- Εντολές μόνες τους: όχι σωλήνας, όχι `; echo $?`.
- Δοκιμή κόκκινη πρώτα για κάθε διόρθωση.
- Οχι rebase, όχι force-push, όχι pkill, όχι συγχώνευση.
- Προστατευμένη διαδρομή μόνο με πηγή (ΦΕΚ, νόμος, ΑΑΔΕ) στο PR.
- Πριν από push: guards, test, typecheck, lint.

Επιστρέφεις: τι βρήκες ως αιτία, τι άλλαξες (αρχεία), αποτέλεσμα των
τεσσάρων ελέγχων, αριθμός PR και SHA αν άνοιξες PR, τι δεν έκλεισε.
```

| Λάθος | Σωστό |
|---|---|
| «Φτιάξε τις δοκιμές» | «Φτιάξε τις τρεις αποτυχίες στο `lib/accounting/bankImport.test.ts`» |
| «Φτιάξε το race condition» | Τα μηνύματα σφάλματος και τα ονόματα των δοκιμών, αυτούσια |
| Χωρίς περιορισμούς | «Μόνο τα αρχεία δοκιμών, όχι κώδικα παραγωγής» |
| «Φτιάξ' το» | «Επέστρεψε αιτία, αλλαγές, αποτέλεσμα ελέγχων» |

## Ανάθεση

Ολες οι αναθέσεις στην ίδια απάντηση τρέχουν παράλληλα. Μία ανά απάντηση τρέχει
στη σειρά.

## Αναμονή

- Οσο έχεις δική σου δουλειά, συνέχισε. Τα αποτελέσματα έρχονται μόνα τους.
- Οταν δεν έχεις, περίμενε σε διαστήματα πέντε με δέκα λεπτών, όχι ανοιχτά
  και σιωπηλά. Ανάμεσα: μία γραμμή κατάστασης και έλεγχος ποιοι πράκτορες ζουν.
  Ετσι ένας κολλημένος φαίνεται σε λεπτά, όχι στο τέλος της συνεδρίας.
- Μην ρωτάς με μικρά χρονικά όρια σε βρόχο.

## Ελεγχος αποτελεσμάτων

Η αναφορά ενός πράκτορα είναι ισχυρισμός, όχι απόδειξη.

1. Διάβασε κάθε σύνοψη.
2. **Συγκρούσεις:** άγγιξαν δύο τα ίδια αρχεία; `git diff --stat` στο καθένα.
3. **Επαλήθευσε ό,τι λέει «πράσινο»:** το CI του PR ή οι τέσσερις έλεγχοι στο
   worktree του. Οι πράκτορες κάνουν συστηματικά λάθη, όπως όλοι.
4. Αν αλλάζει η σειρά συγχώνευσης (ένα PR χρειάζεται το άλλο), γράψ' το στις
   περιγραφές τους.
5. Κάθε PR παραδίδεται με `paradosi`. Κανένα δεν συγχωνεύεται από πράκτορα.

Για σχέδιο με εξαρτώμενες εργασίες σε ένα κλαδί: `anathesi`, όχι αυτό.

Προέλευση και άδεια: `references/proeleusi.md`.
