# mydata-sync

Ο λογιστής φέρνει από το myDATA της ΑΑΔΕ τα παραστατικά εξόδων των πελατών
του που (α) είναι χρήστες PROPERWISE, (β) τον έχουν συνδέσει μέσα στο
PROPERWISE και (γ) έχουν πατήσει «Επιτρέπω». Ποτέ άλλων.

Πηγή: ΑΑΔΕ, «myDATA REST API, Τεκμηρίωση για χρήστες ERP» v2.0.2 (09/2026),
§4.1 (κεφαλίδες `aade-user-id` και subscription key), §4.2 (RequestDocs με
`entityVatNumber` όταν καλεί λογιστής, `mark`, `nextPartitionKey`/`nextRowKey`).

## Ενέργειες (`body.action`)

| action | Ποιος καλεί    | Τι κάνει |
|--------|----------------|----------|
| `sync` | λογιστής (JWT) | «Φέρε τώρα»: `aadeUserId` και `key` στο σώμα. Ανά 5 λεπτά, εκτός αν το προηγούμενο τρέξιμο απάντησε `partial` |

Ε2 (απόφαση ιδιοκτήτη 24/11/2026): **το κλειδί δεν φυλάσσεται πουθενά** και η
άντληση γίνεται **μόνο όταν την ξεκινά ο λογιστής**. Κανένα cron, καμία νυχτερινή
άντληση, καμία αυτόματη επανάληψη. Πριν από την πρώτη άντληση το γραφείο αποδέχεται
τη ρύθμιση άρθρου 26 (`mydata_joint_accept`, έκδοση και ώρα). Η εφαρμογή καλεί με
`region: eu-central-1` (Φρανκφούρτη).

## Μεταβλητές

| Μεταβλητή             | Τιμές                    | Προεπιλογή |
|-----------------------|--------------------------|------------|
| `MYDATA_SYNC_ENABLED` | `1` για να τρέξει        | κλειστό (απαντά 503 `disabled`) |
| `MYDATA_ENV`          | `dev`, `prod`, `fake`    | `dev` (το δοκιμαστικό της ΑΑΔΕ· ποτέ η παραγωγή χωρίς ρητό `prod`) |
| `MYDATA_FAKE_URL`     | μόνο `http://127.0.0.1:…` ή `localhost` | κανένα |

Στην εφαρμογή η ίδια σημαία είναι `NEXT_PUBLIC_MYDATA_SYNC=1`.

## Δοκιμή χωρίς κλειδιά ΑΑΔΕ

```bash
node scripts/mydata-fake/server.mjs          # ψεύτικο myDATA στο 127.0.0.1:8787
# στη συνάρτηση: MYDATA_SYNC_ENABLED=1 MYDATA_ENV=fake MYDATA_FAKE_URL=http://127.0.0.1:8787
# στη «Σύνδεση myDATA», με «Φέρε τώρα»: user id fake-user, κλειδί fakeKeyOnlyForTests0000 (δεν είναι πραγματικά διαπιστευτήρια)
```

Οι δοκιμές του κινητήρα τρέχουν ήδη απέναντι σε αυτόν τον διακομιστή
(`supabase/functions/_shared/mydataEngine.test.ts`).

## Δοκιμή με τα δοκιμαστικά κλειδιά της ΑΑΔΕ

1. Εγγραφή στο δοκιμαστικό περιβάλλον myDATA REST API (mydataapidev) με
   λογαριασμό λογιστή· η ΑΑΔΕ δίνει user id και subscription key.
2. Ενας δοκιμαστικός πελάτης εξουσιοδοτεί τον λογιστή στο myAADE (ορισμός
   λογιστή) και έχει στο δοκιμαστικό τουλάχιστον ένα παραστατικό εξόδου.
3. `supabase secrets set MYDATA_SYNC_ENABLED=1 MYDATA_ENV=dev` και
   `supabase functions deploy mydata-sync --no-verify-jwt` στο staging.
4. Στο staging: ο πελάτης συνδέει τον λογιστή και συμπληρώνει ΑΦΜ. Ο λογιστής
   αποδέχεται τη ρύθμιση και πατά «Επιβεβαίωση ΑΦΜ» στη γραμμή του πελάτη. Μετά ο
   πελάτης πατά «Επιτρέπω» και ο λογιστής δίνει user id και κλειδί με «Φέρε τώρα».

## Ασφάλεια

- Ο λογιστής βγαίνει από το JWT· οι πελάτες που ζητούνται τους κρίνει η βάση
  (`mydata_sync_targets`) και ξαναελέγχεται η άδεια πριν από κάθε σελίδα.
- Το κλειδί έρχεται στο σώμα κάθε κλήσης, μπαίνει μόνο στις κεφαλίδες της
  §4.1 και ξεχνιέται με το τέλος της. Ο φύλακας `scripts/guard-mydata-key.mjs`
  απαγορεύει να φτάσει σε log, απάντηση, μήνυμα σφάλματος, κλήση της βάσης ή
  αποθήκευση του φυλλομετρητή. Απαγορεύει και κάθε συνάρτηση ή cron που θα το φύλαγε.
- Τα σφάλματα στη βάση είναι κωδικοί από κλειστό κατάλογο, ποτέ κείμενο.
- Το ΑΦΜ της άδειας το επιβεβαιώνει ο λογιστής και πρέπει να συμφωνεί με το
  προφίλ χρέωσης του πελάτη. Ενα ΑΦΜ έχει μία ενεργή άδεια.
- Ορος γραφείου ή σύνδεσμος που έληξε: παύση, όχι διαγραφή. Αποσύνδεση, νέο
  token, αφαίρεση από γραφείο ή ανάθεση: ανάκληση αμέσως (σκανδάλες στο τέλος
  της συναλλαγής, `private.mydata_revoke_dead`).
- Παραστατικό που η ανάγνωση δεν δέχεται: καραντίνα (`mydata_quarantine`), ο
  ΜΑΡΚ σταματά πριν από αυτό, ειδοποίηση μόνο με κωδικό (`invalid_invoice`).
- Οσοι δεν πρόλαβαν μέσα στα 140″: η απάντηση λέει `partial` και η κάρτα του
  λογιστή ξαναπατά με το ίδιο κλειδί όσο είναι ανοιχτή η καρτέλα. Κάθε πελάτης
  συνεχίζει από το σημείο συνέχισης.
