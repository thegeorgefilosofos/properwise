# Απόδοση: τα πρώτα νούμερα

Μέχρι τις 23 Αυγούστου 2026 η απόδοση δεν είχε **κανένα** νούμερο. Δεν ξέραμε
αν η αρχική σελίδα κατεβάζει 300 KB ή 3 MB, ούτε αν το Χαρτοφυλάκιο με 200
ακίνητα ανοίγει σε δύο δευτερόλεπτα ή σε είκοσι. Τώρα ξέρουμε και τα δύο και
δύο καστάνιες τα κρατούν.

## Τι μετρήθηκε

### Βάρος δημόσιων οθονών · `npm run perf:budget`

Πραγματικός περιηγητής, παραγωγικό build, **άδεια μνήμη σε κάθε οθόνη**. Με
κοινή μνήμη η δεύτερη οθόνη «ζυγίζει» σχεδόν μηδέν επειδή μοιράζεται τα κοινά
αρχεία και το νούμερο δεν θα ήταν κανενός επισκέπτη.

Το όριο ζει στο `budget.json` και **μόνο κατεβαίνει**: ανοχή 8%.

    npm run build && npx next start -p 3100
    node scripts/perf-budget.mjs            # έλεγχος
    node scripts/perf-budget.mjs --write    # καταγραφή νέου ορίου

#### Νέα βάση από την πύλη του CI (11/11/2026)

Οι βάσεις είχαν γραφτεί στις 19/10/2026 (cfff82c, #406) και δεν άλλαξαν από
τότε. Σε 97 συγχωνεύσεις οι σελίδες άλλαξαν βάρος μέσα στην ανοχή: ανέβηκαν
με λειτουργίες (π.χ. η αγγλική βιτρίνα στη σύνδεση και την εγγραφή, #467)
και ξανάπεσαν με τα #468 και #534. Το `--write`
μόνο κατεβάζει, οπότε καμία βάση δεν ξαναγράφτηκε και σε 6 από τις 8 οθόνες
η ανοχή του 8% είχε γίνει μόνιμο περιθώριο (στο /signup έμεναν 4,3 KB).

Η διαφορά δεν ήταν διαφορά μέτρησης. Στο ίδιο δέντρο το CI και το τοπικό
μηχάνημα δίνουν τα ίδια νούμερα ως το δέκατο του KB, σε όλες τις 8 οθόνες.

Μέθοδος: η μέτρηση της ίδιας της πύλης (`perf:budget` στο job «Ο,τι κρίνεται
αφού ζωγραφιστεί»), CI 43032171903, merge ref 5e10299 = main 5dd7890 συν την
εκτύπωση των bytes. Γράφτηκαν `initial` και `js` όπως τα μέτρησε· το `total`
μετρά ως την ηρεμία του δικτύου και αλλάζει από τρέξιμο σε τρέξιμο, δεν κρίνεται.
Η ανοχή μένει 8%. Έγκριση ιδιοκτήτη για άνοδο όπου χρειάζεται, 11/11/2026.

### Απόδοση με 200 ακίνητα · `npm run perf:bench`

Ο πάγκος προσαρτά το **πραγματικό** `PortfolioTab` με χαρτοφυλάκιο 200
ακινήτων: 2.400 δόσεις ενοικίου, 900 διαμονές, 2.000 λογαριασμοί, 1.600
δαπάνες. Χωρίς διακομιστή και χωρίς λογαριασμό.

| Ακίνητα | Ετοιμο | Ταξινόμηση |
|---|---|---|
| 3 | 76 ms | 66 ms |
| 50 | 129 ms | 96 ms |
| 200 | **302 ms** | 147 ms |

Διάμεσος από τρεις εκτελέσεις. Ανοχή 35%, γιατί ο χρόνος έχει θόρυβο ενώ τα
bytes όχι.

## Τι ΔΕΝ μετρήθηκε και δεν πρέπει να θεωρηθεί εντάξει

**Το δίκτυο και η βάση.** Ο πάγκος απαντά ακαριαία, οπότε μετρά ΜΟΝΟ τον δικό
μας κώδικα. Με 200 ακίνητα η βάση επιστρέφει περίπου 7.000 γραμμές σε έντεκα
παράλληλα ερωτήματα· πόσο κοστίζει αυτό στην πραγματική Supabase, με πραγματικό
δίκτυο και πραγματικά RLS policies, **παραμένει άγνωστο**. Τα 302 ms είναι το
κάτω όριο του τι θα δει ο χρήστης, όχι η πρόβλεψη.

**Ο πίνακας ελέγχου συνολικά.** Μετρήθηκε το Χαρτοφυλάκιο, που είναι η βαρύτερη
οθόνη. Οι υπόλοιπες δεκαπέντε καρτέλες δεν έχουν πάγκο.

**Κινητό.** Ολα τα νούμερα είναι από επιτραπέζιο, σε 1440×900. Ενα τηλέφωνο
τριών ετών είναι τρεις ώς πέντε φορές πιο αργό στον ίδιο κώδικα.
